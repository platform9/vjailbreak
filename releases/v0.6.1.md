# v0.6.1

- **Tag:** `v0.6.1`
- **Published:** 2026-11-20T09:11:04Z
- **Source release:** https://github.com/platform9/vjailbreak/releases/tag/v0.6.1

## Release Notes

## Highlights

- **Storage-Accelerated Copy across several arrays**: ArrayCreds are now chosen per VM, so one migration plan can cover VMs on different arrays, including a single VM whose disks sit on more than one array.
- **Hot migrations are more stable during Periodic Sync**:
  - A intermittent vCenter error no longer marks a running migration Failed.
  - A new stall watchdog prevents changed-block copy from staying unresponsive forever.
- **vJailbreak Accelerated Copy (Hot-Add) is more reliable**: Concurrent migrations never compete for a port, avoiding a race condition during concurrent migrations. 
- **vAssessment (beta)**: a separate appliance for pre-migration readiness checks, with a web UI, scoping, readiness groups and diagnostics. Beta version available as OVA.

## Bug Fixes

- Fixed the Convert phase failing with "no operating system found": each disk is now checked for readiness after it is attached to the vJailbreak VM, before virt-v2v runs.
- Fixed qemu-nbd not being confirmed as listening after an NBD server restart.
- Fixed Retry silently changing Standard Copy to vJailbreak Accelerated Copy.
- Fixed false subnet-mismatch warnings for multi-NIC VMs on different networks. Persist source network interfaces is no longer greyed out for these VMs.
- Fixed ArrayCreds rejecting valid volume types when a Cinder backend has more than one volume type.
- Fixed issues for Windows dynamic disk (LDM) migrations.

## Security

- Rebuilt the Hot-Add proxy OVA to fix the sshole vulnerability (CVE-2026-123158).

## Known Limitations

- **Hot-Add stale snapshots**: snapshots left by failed Hot-Add migrations can pile up and cause UUID conflicts. Remove them in vCenter before retrying.
- **SUSE Linux Enterprise HPC 15 SP5 is not supported**: virt-v2v doesn't recognise `sle_hpc`.
- Users upgrading in-place from v0.5.0 or v0.6.0 to this version may hit a known issue during upgrade. Retrying the upgrade should resolve it automatically.
